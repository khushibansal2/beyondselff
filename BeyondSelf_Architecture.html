Section 01

Project Overview

BeyondSelf is a full-stack "Digital Twin" life management web application. It tracks health, finance, and career data to produce unified life scores and AI-driven coaching — all without exposing user PII to external AI services.

🧠
Deterministic Scoring
All life scores are pure math — same input always gives the same output. No ML hallucination in core scoring.
🤖
AI for Narration Only
Groq LLM explains scores computed by engines. It never invents numbers or raw metrics.
📴
Offline-First
Full scoring works client-side via demo personas. Spring Boot backend is optional — adds persistence & file parsing.
🔗
Cross-Domain Intelligence
Detects how one life domain affects another: sleep debt → emotional spending → financial score decline.
🛡️
PII Protection
Name, email, and ID are stripped before any data is sent to Groq — both at frontend and backend layers.
📂
Multi-Format Ingestion
Import PDF bank statements, CSV health logs, Excel career data — normalized automatically via backend parsers.

Section 04

Data Flow

From raw file upload to AI narrative — every transformation step in the pipeline.

1 — User Input / File Upload
User logs data manually (health vitals, expenses, career skills) OR uploads a PDF bank statement, CSV health log, or Excel file via the Upload page.
2 — Backend File Parsers
PDFBox extracts text from PDFs → OpenCSV parses CSV rows → Apache POI reads Excel sheets. Raw data lands in UploadService.
3 — Normalizers
HealthNormalizer, FinanceNormalizer, CareerNormalizer map heterogeneous raw data into a unified domain schema (typed fields, date normalization, unit conversion).
4 — JPA → Database
Normalized records persisted via Spring Data JPA repositories to H2 (dev) or PostgreSQL (prod). Each record is user-scoped via JWT-verified user ID.
5 — Frontend Sync
syncService.js calls GET /api/sync to bulk-fetch all records → dispatches ADD_RECORDS action to DataContext. Imported data always overrides demo seed data.
6 — Scoring Engines (client-side)
DataContext state change triggers lifeBalanceEngine to recompute all domain scores, cross-domain cascades, burnout risk, and anomalies. No network call required for scoring.
7 — AI Narration
aiService.js strips PII and sends computed scores only to POST /api/ai/chat (backend Groq proxy). Groq returns a narrative. Falls back to deterministic template if API unavailable.
8 — Rendered to User
Dashboard, charts, coach responses, simulator projections, and gamification state all reflect the same computed truth from DataContext.
Section 05

Scoring Engine Architecture

All six engines are deterministic pure-function JavaScript modules. No randomness, no ML — same input always produces the same score. This is critical for user trust and auditability.

Life Balance Engine lifeBalanceEngine.js
Orchestrator — combines all three domain scores with a weighted formula. Applies burnout and sleep penalties. Detects cross-domain cascade effects.
balance = health×0.35 + finance×0.30 + career×0.35
− burnoutPenalty (15 if risk>60, 8 if risk>30)
− sleepPenalty (10 if avg<6hrs)
Health Score Engine healthScoreEngine.js
Scores sleep quality, stress levels, BMI, exercise frequency, and hydration. Also computes burnout risk score (0–100) from work hours + sleep debt.
factors: sleep, stress, BMI,
exercise, hydration
burnoutRisk: workHours + sleepDebt
Finance Score Engine financeScoreEngine.js
Calculates savings rate, debt-to-income ratio, emergency fund runway, and spending trend direction. Flags financial stress states.
factors: savingsRate, debtRatio,
emergencyRunway, spendingTrend
stressFlag: runway < 3 months
Career Score Engine careerScoreEngine.js
Evaluates skill depth, career trajectory momentum, GitHub activity integration, and learning investment percentage of time.
factors: skillDepth, trajectory,
githubActivity, learningInvestment
readiness: upskilling focus score
Simulator Engine simulatorEngine.js
Projects habit changes forward 3–12 months. Includes burnout crash prediction curve. Compound improvements and decay curves are modeled per habit type.
projection: monthlyCurve[0..12]
burnoutCrash: tipping point detection
compoundEffect: per habit category
Neural Engine NeuralEngine.js
TensorFlow.js sequential model running entirely in-browser. Takes 3 domain scores as input, outputs 2-class softmax prediction. Visualized live on the NeuralCore page.
layers: Dense(16,relu) →
Dense(8,sigmoid) → Dense(2,softmax)
optimizer: Adam | loss: categoricalCE
⚡
Cross-Domain Cascade Effects (unique to this project)

The Life Balance Engine detects three specific cascades automatically: (1) Sleep debt → emotional spending spikes, (2) Financial stress → career readiness decline, (3) Financial runway < 3 months → forced upskilling focus. These are surfaced as urgent alerts on the Dashboard.

Section 08

AI Architecture — Dual-Path Groq Integration

AI is used exclusively for narration and coaching, never for raw score computation. Two distinct paths handle different use cases with different security requirements.

🌐 Path A — Frontend → Groq Direct (no PII path)

Used by: Vision analysis, nutrition parsing, learning plans, resume intelligence, gamification quests, banking categorization. The API key is stored in VITE_GROQ_API_KEY env var or user localStorage. No user PII is ever included in these payloads.

Used by: AI Coach chat, dashboard narrative, insight explanations. The Groq API key lives only on the server. The frontend sends computed scores, never raw user data. The backend performs an additional PII strip before forwarding.

🛡️
Fallback Strategy

On 429 (rate limit) or network failure, aiService.js activates the deterministic template fallback (RoboAdvisor). It generates coaching text grounded in the computed engine outputs — so the coach stays intelligent and specific even when Groq is unavailable. No generic fallback text.

Section 09

State Management

All application state flows through two React Contexts. No Redux, no Zustand — the architecture is deliberately lean.

AuthContext
JWT token management, demo user fallback, localStorage session persistence. Provides user and loading state to ProtectedRoute.
DataContext (useReducer)
13 action types: SET_USER_DATA, UPDATE_DOMAIN, ADD_RECORDS, SET_RECORDS, UPDATE_GOALS, ADD_GOAL, DELETE_GOAL, ADD_TIMELINE_EVENT, UPDATE_GAMIFICATION, UPDATE_AI_CACHE, UPDATE_SIMULATOR_STATE, RESET, HYDRATE.
storageAdapter.js
Handles localStorage versioning and schema auto-migration. All pages use this instead of raw localStorage to prevent stale data bugs across app updates.
Cross-Tab Sync
DataContext listens to window storage events to synchronize state across multiple open browser tabs in real time.
Data Priority
Real imported data always overrides demo seed data. dataSource field tracks state: 'none' | 'demo' | 'imported' | 'mixed'.
AI Cache
Computed dashboard narratives are cached in DataContext with a content hash. Groq is only called when the underlying data actually changes — minimizes API usage.
Section 10

Unique Features

What differentiates BeyondSelf from a standard life-tracking app.

🔗
Cross-Domain Cascade Engine
Automatically detects and surfaces how one life domain hurts another: sleep debt triggers emotional spending spikes, financial runway below 3 months forces upskilling focus, financial stress causes career readiness decline.
👻
Ghost Timeline
Shows what your life metrics looked like at past milestones. Creates a visual "ghost" overlay of your historical self to compare against your current trajectory.
☠️
Doom Mode
A dark-pattern simulator that projects the worst-case consequences of continuing bad habits. Shows burnout crash curves, financial ruin timelines, and career stagnation paths.
🏪
Life Market
A gamified decision negotiation system where users trade life decisions (sleep hours vs. work hours) and Groq AI evaluates the fairness and long-term value of each trade.
🧠
In-Browser Neural Network
TensorFlow.js neural network running entirely in the browser — no server. Takes the 3 domain scores as input, trains in real time, and visualizes activations on the NeuralCore page.
🤝
India-Specific Banking
Native integration with Indian banking formats — UPI transaction parsing, NEFT/IMPS statement categorization, and CIBIL score correlation. Built specifically for the Indian market.
Section 11

Security Design

🔑
JWT Authentication

Stateless JWT tokens (24h expiry, signed with secret key). All protected endpoints verify the token via AuthUtil before processing.

🔐
BCrypt Password Hashing

Passwords are never stored in plaintext. Spring Security Crypto BCrypt with default cost factor applied at signup.

🛡️
PII Stripping (2-layer)

aiService.js strips PII before sending to backend. GeminiService.java strips again server-side before forwarding to Groq. Belt-and-suspenders approach.

🌐
CORS Configuration

Backend explicitly allows only React dev server origins (ports 5173–5176). CorsConfig.java prevents unauthorized cross-origin requests.
